# Opportunity evidence workflow

Use opportunities_list filters type, page_url, min_impact, effort and data_basis to narrow the stored evidence. view: weekly returns at most ten findings with at most three per primary type. optional opportunity_id returns scoped detail, formulas, source coverage, confidence reasons and supporting findings. status: snoozed lists the saved resume date. MCP stays read-only; suggest the existing authenticated detail controls for snooze or status changes.

One primary finding represents each normalized query or page, with other rule observations attached as supporting evidence. Do not add estimates from overlapping rules. Done, dismissed and snoozed decisions suppress equivalent open findings. An incomplete 5,000-row catalog withholds open groups. Missing/stale imports never prove resolution.

Read calibrated CTR, confidence, value, effort, prerequisites, planning time-to-value and realization-factor evidence before recommending work. Review indexing/noindex/canonical prerequisites first. Recent annotated/watched changes warrant measuring before acting; their association with a decline is not proven cause. Audit/vitals exposure is not an incremental gain prediction.

Outcome comparisons use a complete preceding 28-day baseline, then days 1–28 and 29–56 after completion, excluding completion day. They are correlations. Calibration uses eligible last-year 56-day observations, five minimum, ten neutral prior observations and a bounded factor; raw predictions remain separate to prevent compounding. Missing data stays pending and unknown gains stay unknown. Inspect result_limits and fetch focused detail when the MCP response is truncated.
